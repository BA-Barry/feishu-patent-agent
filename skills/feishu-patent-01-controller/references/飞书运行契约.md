# 飞书运行契约

本契约适用于 01–12 全部节点。专利判断和内容生成由 AI 完成；飞书负责读取项目状态、保存过程和成果、承载确认事项。仅把最终文本粘贴到飞书不算完成节点。

## 账号与可移植性

- 每次运行都显式使用 `--profile <账号配置名>`；未指定时使用 `default`。
- 开始节点前执行 `preflight`，核验 `identity=user`、当前账号、租户、项目键和飞书中的当前节点。
- 不在 Skill、交接文件或项目目录中保存 App Secret、用户令牌或 Cookie。认证资料只由飞书 CLI 的账号配置管理。
- 同一项目的不同账号分别写入 `.patent-feishu/accounts/<profile>.json`；不得复用另一个账号的本地状态。
- 换账号、换电脑或换租户时，重新完成该账号的飞书 CLI 登录，再用 `attach` 绑定现有多维表格项目；12 个 Skill 本身不需要改写。

## 唯一业务主账本

飞书多维表格是跨节点状态的业务主账本，包含四张表：

- `专利项目`：项目键、当前节点、状态、下一节点、质量门、可继续、阻断原因和成果入口。
- `节点运行`：每次节点尝试的输入摘要、输出摘要、开始/完成时间和质量门结果。
- `确认事项`：发明人需要回答的技术事实、范围选择和流程确认；不承载与技术流程无关的固定口令。
- `成果索引`：云文档或附件成果、版本、来源、哈希和验证状态。

本地 `交接/下一节点输入.json` 继续作为可审计交付物，但不得单独决定远端项目状态；发布节点时将其 SHA-256 回写飞书。

## 标准调用

安装后运行脚本位于 `.agents/patent-feishu-runtime/patent_feishu.py`。以下命令均在目标项目根目录执行：

```text
python .agents/patent-feishu-runtime/patent_feishu.py preflight --profile <profile> --project-key <项目键> --expected-stage <节点编号>
python .agents/patent-feishu-runtime/patent_feishu.py start-stage --profile <profile> --project-key <项目键> --node <节点编号>
python .agents/patent-feishu-runtime/patent_feishu.py publish-stage --profile <profile> --project-key <项目键> --node <节点编号> --next-stage <下一节点或END> --summary <摘要> --handoff-file <交接文件>
```

01 首次创建飞书主账本时使用 `bootstrap`；连接已有主账本时使用 `attach`。需要发明人确认时，先使用 `ask` 写入 `确认事项` 表。

## 节点门槛

1. 先运行 `preflight`。远端当前节点、账号或项目键不一致时立即停止，不读取后续材料。
2. 运行 `start-stage`，在 `节点运行` 表建立本次尝试记录。
3. 读取飞书项目状态、上游云文档/附件和本地只读材料；记录事实来源。
4. AI 执行本节点的分析、生成或质量判断。
5. 需要人工选择时，用 `ask` 写入确认事项并停止；收到明确结果后再继续。
6. 生成本地交付文件和 `交接/下一节点输入.json`。
7. 使用 `publish-stage` 创建/更新飞书云文档、成果索引、节点记录和项目当前节点。
8. 仅当返回 JSON 的 `ok=true`、质量门允许继续且远端回读一致时，节点才算完成。

## 外部通知与高风险操作

- 写入多维表格和云文档属于本工作流的常规动作。
- 向群聊发消息或创建任务前，必须向用户展示收件人、内容、发送身份并取得本次明确同意；随后才可同时传入 `--send-notification --notification-approved`。
- 飞书 CLI 返回高风险确认（退出码 10）时必须停止并让用户人工确认；不得自动追加 `--yes`。
- 写入失败、授权过期、权限不足或回读不一致时，不得假装完成，也不得推进下一节点。
