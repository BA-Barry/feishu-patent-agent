# 三分钟真实 Demo 脚本

目标时长：2 分 40 秒至 2 分 55 秒。先展示能力和效果，再展示核心过程。全程录真实运行，不使用纯 PPT 代替产品。

## 录制前准备

1. 使用 `Demo匿名素材.md`，不要放入真实未公开发明资料。
2. 新电脑第一个飞书账号使用 Profile `default`。
3. 创建匿名项目：

```powershell
python .\.agents\patent-feishu-runtime\patent_feishu.py bootstrap --profile default --project-key PAT-DEMO-001 --project-name "防烫保温杯匿名演示"
```

4. 在 Codex 中准备以下启动提示：

```text
开始发明专利。飞书账号 profile 是 default，项目键是 PAT-DEMO-001。请读取 Demo匿名素材.md，识别技术披露缺口，并将项目状态、待确认事项和阶段成果写回飞书。
```

5. 预先打开飞书多维表格、Codex 和生成的阶段云文档，录屏时隐藏通知和个人信息。

## 0:00–0:20 先看结果

画面：打开飞书多维表格项目看板，快速切换 `专利项目`、`节点运行`、`确认事项`、`成果索引`。

旁白：

> 这是飞书专利 Agent。一个零散发明想法进入后，AI 会判断缺口、执行检索和撰写，飞书则持续保存每个节点、待确认问题、质量门和成果版本。所有判断和成果都能追溯。

## 0:20–0:40 用户痛点与价值

画面：展示输入材料入口和项目当前节点。

旁白：

> 专利协作最麻烦的不是生成一段文字，而是材料分散、版本混乱、跳步骤，以及发明人不知道该确认什么。这个产品把 12 个专业节点变成一条飞书内可见、可暂停、可恢复的流程。

## 0:40–1:10 启动与材料评估

画面：在 Codex 输入“开始发明专利，profile 为 default，项目键 PAT-DEMO-001”；随后展示终端预检结果和飞书节点状态变为运行中。

旁白：

> 节点开始前，系统先校验当前飞书账号、租户、项目键和远端节点。然后读取飞书中的材料链接和已有初稿，AI 评估 04 到 12 的就绪度，不按文件名猜测，而是路由到最早的真实缺口。

## 1:10–1:40 AI 判断与飞书确认闭环

画面：展示 AI 识别出一个技术事实冲突；飞书 `确认事项` 新增一行，项目状态变为待确认；在飞书填写回应后继续。

旁白：

> 遇到关键结构冲突，AI 不会自行编造。它把问题写进飞书确认事项并暂停。发明人确认后，下一次运行回读这个结果，再继续形成问题—手段—效果链。

## 1:40–2:15 阶段成果与质量门

画面：打开生成的飞书阶段云文档，再切到 `成果索引`，展示版本、SHA-256、来源和验证状态。

旁白：

> 每个阶段不只是产出文本。AI 同时给出证据链和质量判断；飞书保存云文档、版本、来源、哈希和可继续状态。质量门不通过时，项目不会被推进到下一节点。

## 2:15–2:38 动态路线与终稿

画面：展示路线从 03 动态进入 08，随后经过 09、10、11、12；快速展示权利要求、附图校验和 Word 终稿索引。

旁白：

> 有成熟初稿时，它可以直接从权利要求等真实缺口继续；没有材料时则完整走技术披露和检索。最终仍要经过附图一致性、说明书支持性和 Word 渲染质量门。

## 2:38–2:55 多账号与收尾

画面：展示两个 Profile 的本地非敏感状态文件名，切回飞书项目总览。

旁白：

> 同一套 Skill 不绑定固定账号。每个飞书账号独立登录、独立保存状态，并受飞书真实权限控制。飞书负责协作与执行，AI 负责专业判断，这才是完整的飞书专利 Agent。

## 录制检查

- 隐去 App ID、账号邮箱、真实姓名、未公开发明内容和任何令牌。
- 至少真实展示一次飞书回读、一次 AI 判断、一次飞书写回。
- 显示质量门或阻断状态，证明并非无条件生成。
- 成片不超过 3 分钟，发布文案带比赛要求的话题标签。
