# 飞书 AI 绝活大会适配说明

## 为什么做

发明人提供的往往是聊天式想法、论文、图纸、初稿或多版本材料。传统协作中，技术事实、检索证据、发明人确认和最终文本分散，容易发生版本混乱、跳过必要阶段、无依据补写和附图不一致。

## 做了什么

飞书专利 Agent 将发明专利工作拆成 12 个可独立复核的 AI 节点，并用飞书多维表格作为业务主账本、飞书云文档作为阶段成果载体：

1. 总控建项目。
2. 盘点并评估已有材料。
3. 动态决定最早需要补齐的节点。
4. 完成技术披露、检索、创新点、摘要、权利要求、附图、说明书和 Word 终稿。
5. 每一步将输入、判断、质量门、待确认问题和成果版本回写飞书。

## 用户获得什么

- 一眼看清当前节点、下一节点、阻断原因和待确认事项。
- 已有初稿可从真实缺口继续，不重复做无价值工作。
- 重要判断与来源绑定，便于发明人和代理师复核。
- 附图与文字经过独立一致性质量门，减少结构漂移。
- 不同飞书账号可以用独立 Profile 运行同一套产品。

## 飞书为什么不可替代

- 节点开始前必须从飞书回读远端项目状态；不一致即停止。
- 材料入口、确认事项、节点运行、质量门和成果索引都在飞书协作层中持续存在。
- 节点完成必须写回多维表格和云文档，并回读验证成功后才能推进。
- 发明人通过飞书确认技术事实，AI 据此继续推理，而不是把飞书当作最终文本展示页。

## AI 为什么不可替代

- 判断材料成熟度并动态路由。
- 构造可复核的中英文检索策略并分析最接近现有技术。
- 建立问题—手段—效果证据链和必要/可选特征层级。
- 生成并审查摘要、权利要求和说明书。
- 规划附图、校验跨图一致性并识别不充分公开或新增内容风险。

## 参赛期新增沉淀

- 将 12 个目录和 Skill `name` 统一为可移植的英文标识。
- 新增飞书多维表格四表模型与云文档成果链。
- 新增运行桥接脚本，强制 `preflight → start-stage → AI 工作 → publish-stage`。
- 新增多账号 Profile 隔离、身份/租户核验和项目绑定机制。
- 新增消息/任务发送的显式确认门，默认只写主账本。
- 新增 Windows/Mac 安装和账号配置脚本。
- 新增比赛产品介绍、三分钟 Demo 及提交核对材料。

## 比赛要求对应

| 比赛要求 | 本产品证据 |
|---|---|
| 飞书参与核心运行 | 多维表格回读/回写、云文档成果、确认事项、可选消息/任务 |
| AI 参与核心运行 | 动态路由、检索分析、内容生成、质量判断和附图一致性校验 |
| 不是简单粘贴结果 | 节点必须以远端状态为前置，并将过程和质量门写回后才可推进 |
| 产品介绍与上手说明 | `README.md`、`使用说明.md` |
| 真实 Demo | `contest/三分钟Demo脚本.md` |
| 既有产品说明新增内容 | `contest/更新记录.md` 与本文件“参赛期新增沉淀” |
