# 飞书专利 Agent

把零散发明想法、已有初稿和技术材料，转化为一条可协作、可追踪、可复核的中国发明专利 AI 工作流。

## 产品简介

传统专利撰写往往散落在聊天、文档、检索记录和多版附件中，项目状态不透明，发明人也很难知道“现在做到哪一步、为什么停、下一步确认什么”。飞书专利 Agent 将 12 个专业节点沉淀为统一流程：AI 负责技术披露分析、检索判断、创新点抽取、摘要/权利要求/说明书生成和附图一致性审查；飞书负责读取项目状态、承载材料与确认事项、保存过程记录和成果，并驱动节点流转。

核心价值：

- 从想法或任意成熟度材料动态起步，不强迫重走已完成阶段。
- 每个结论都能回到材料、检索证据、确认事项和质量门。
- 多维表格展示项目、节点、待确认事项和成果版本；云文档保存可读阶段成果。
- 12 个 Skill 不绑定固定账号，通过飞书 CLI Profile 在不同账号和电脑运行。
- 保留本地交付文件、哈希和远端记录，便于恢复、复核和交接。

## 飞书与 AI 的核心分工

| 环节 | 飞书 | AI |
|---|---|---|
| 输入 | 读取多维表格状态、云文档、附件和确认结果 | 识别材料类型、缺口和事实冲突 |
| 处理 | 保存节点运行、确认事项、版本与质量门 | 检索、分析、判断、生成、校验和动态路由 |
| 输出 | 写回云文档、成果索引、下一节点和阻断原因 | 生成摘要、权利要求、说明书、附图方案及审查意见 |

没有飞书回读与回写，节点不得完成；没有 AI 的分析或判断，飞书记录也不会自行推进。因此本产品不是把生成文本简单粘贴到飞书。

## 快速开始

1. 将本包安装到目标项目。

```powershell
powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -ProjectRoot "C:\你的\项目"
```

2. 为当前飞书账号创建独立 Profile 并登录。

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-feishu-account-windows.ps1 -Profile default
```

3. 在目标项目中创建飞书主账本。

```powershell
python .\.agents\patent-feishu-runtime\patent_feishu.py bootstrap --profile default --project-key PAT-001 --project-name "示例发明"
```

4. 在 Codex 中输入：

```text
开始发明专利。飞书账号 profile 是 default，项目键是 PAT-001。
```

5. 系统依次运行 01–03，并根据材料成熟度动态进入 04–12。每个节点都在飞书中生成可见状态和成果。

Mac 命令和完整说明见 [使用说明.md](使用说明.md)。

## 多账号

新电脑上的第一个账号使用 `default`，让官方安装流程创建一次默认应用即可。同一电脑再增加其他账号时使用命名 Profile，例如 `lisi`；不同租户会为该 Profile 创建独立应用。继续既有项目时使用 `attach` 绑定该账号有权访问的飞书多维表格记录。Skill、运行脚本和数据模型均不需要按账号改写。

## 交付内容

- 12 个规范化 Skill：`skills/feishu-patent-*`
- 飞书运行桥接：`runtime/patent_feishu.py`
- Windows/Mac 项目级安装器与账号配置脚本
- 比赛产品介绍、Demo 脚本、提交清单和更新记录：`contest/`

> 本工具生成的是专利撰写辅助材料，不替代执业专利代理师的正式审查与申请决策。
